# Onboarding experiment: results

*Example report for `stataudit check-report`. It reads like a typical
assistant-written write-up; three of its eight reported results do not match
their own test statistics.*

Participants in the new onboarding flow finished setup faster than those in the
old flow, *t*(72) = 2.31, *p* = .024, *d* = 0.62. Satisfaction ratings did not
differ, *t*(72) = 1.12, *p* = .27.

Completion depended on the pricing plan, χ²(2, *N* = 210) = 6.40, *p* = .041, and
time on task was negatively related to prior experience, *r*(70) = −.28,
*p* = .017.

The three onboarding variants differed in the number of errors,
*F*(2, 69) = 2.95, *p* = .03. Support tickets per user dropped after the
launch, *z* = 1.70, *p* < .05, and weekly active usage rose,
*t*(35) = 2.04, *p* = .03.

The manipulation check confirmed that participants noticed the new flow,
*F*(1, 70) = 48.3, *p* < .001.
